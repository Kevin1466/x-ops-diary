## 2026-11-05 · Day 1：先把工具搭起来

### 今天做了什么

从零搭了两个 Chrome 扩展，用来替代“手动刷时间线 + 手动复制粘贴”的原始流程。

**1. 互动辅助**

原本是一个“全自动点赞/关注/回复”的脚本，今天做了一次大改：

- 动作模型从「7 种固定组合随机抽」改成「关注 / 点赞 / 回复 各自独立掷骰子」，概率可配（默认 45 / 70 / 60）
- 加了调度状态机：首页选帖 → 详情页 → 处理评论区 → 回首页继续下一个，一轮可配 N 个帖
- 加了「单动作冷却」：被限流时只冻结那一类动作，其它继续

**2. 内容自动化**

需求写得很完整，落地时砍掉一半：

- 原计划 5 大板块、20 个信源、100 位大佬的 X 账号
- 实际改成 **DeepSeek 搜索 API + 5 个板块 10 条检索式**，一次探测约 0.0075 美元
- 流程：探测 → 去重/时效过滤 → 打分 → Top 3 → 弹审批小窗（5 分钟倒计时）→ 采纳后浏览器自动化发帖

### 关键决策

**不用 RSS，改用搜索 API。** 20 个源意味着 20 个解析器要维护，官方博客一改版就全断；X 账号还要过 RSSHub，稳定性差。搜索 API 一次请求就把“发现 + 时效 + 权威度”都拿到了，还自带 `rerank_score`（0–3）和 `authority`（0–4）两个可用的排序信号。

**发帖不走官方 API。** 官方接口要 OAuth + 付费档位，而我现在只有单账号、每天 2–4 条的频率。浏览器自动化虽然脆，但零成本、复用已有登录态。等发布量上来或需要数据回流时再换。

**审批加 5 分钟倒计时。** 没有倒计时，候选会一直躺着，等于没有自动化；倒计时太短，等于无人审核。第一周自动发送保持关闭，只看候选质量。

### 踩坑

**回复内容重复一遍。** 往 X 的编辑器写文本时，习惯性先全选再插入。但编辑器为空时，全选会退化成选中整个页面，插入被执行两次 → 文本重复。改成：只在非空时清空，写完回读校验，不一致就重写一次，仍不一致宁可不发。

**右键菜单一层层堆叠。** `querySelector('[role="menu"]')` 永远返回最旧的那个菜单。上一个没关掉，下一个用户就会拿着别人的菜单去匹配「Follow @xx」，永远匹配不到。改成：操作前先清场，只取最新的菜单节点，识别到 `Unfollow` 就收手。

**限流一刀切。** 关注被限流时整轮都停了，点赞和回复本来还能继续。改成按提示文案判断类别，只冻结那一类，冷却时长可配。
